# AGENTS.md — Авто-паркур

Инструкция для разработчиков и ИИ-агентов. Здесь описано, как устроена игра, как генерируются
уровни и как добавить новое препятствие, не ломая остальные.

## Команды

```bash
npm run dev          # игра на http://localhost:5173 (в dev-режиме доступен window.__dev)
npm run typecheck    # tsc --noEmit, должен проходить без ошибок
npm run levels -- 200            # сгенерировать уровни 1..200 и проверить их (уникальность, высоты, структура)
npm run levels -- --plan 12      # JSON-план уровня 12
npm run levels -- --catalog      # таблица каталога препятствий (markdown)
npm run build        # typecheck + продакшн-сборка в dist/
```

Перед сдачей изменений: `npm run typecheck` и `npm run levels -- 200` должны проходить.

## Соглашения

- Единицы — метры, секунды, м/с. Ось Y вверх.
- Курсор трассы `{ p, yaw }`: точка на осевой линии **на поверхности дороги** и курс.
  `yaw = 0` — вдоль +Z; рост yaw = поворот **влево**, правый поворот уменьшает yaw.
- Локальные координаты относительно курсора — `local(c, x, y, z)`: x — вправо, y — вверх, z — вперёд.
- Машина в своих координатах: +Z вперёд, +X влево, +Y вверх.
- Коллизии: трасса `TRACK_GROUPS`, машина `CAR_GROUPS`, обломки `DEBRIS_GROUPS`. Лучи колёс видят только трассу.
- Trimesh-коллайдеры создаются с `FIX_INTERNAL_EDGES` (иначе машина цепляется за стыки треугольников).
  Rapier **не отдаёт импульсы контактов для trimesh**, поэтому удары считаются по изменению скорости
  машины в точке контакта (`Vehicle.afterStep`).
- Движущиеся препятствия — только кинематические тела через `TrackBuilder.addKinematic(object, pose(t), colliders)`.
  Поза задаётся аналитически от времени `t`: это даёт детерминизм, правильную скорость поверхности для шин
  (`MovingSurface.velocityAt`) и сминание машины (`damage.crush`) при давлении лопастью.
- Всё, что создаёт уровень, должно идти через `TrackBuilder` (`collider()`, `own()`, `addKinematic()`, `addDecor()`),
  иначе оно не освободится при смене уровня.
- Тексты для игрока — на русском.

## Правила дизайна (пожелания владельца проекта)

- **Никаких узких препятствий**: обычная дорога 20 м, посадочные зоны и площадки 24 м и шире (кроме полотна петли — 14 м).
- Опасность создают **винты и движущиеся массы**, которые сбивают машину с трассы и сминают её.
- Машина тяжёлая (1650 кг, гравитация ×1.35), хрупкая, но не «картонная». Разбитый мотор почти не снижает скорость.
- В воздухе W/S дают **очень слабый** наклон, A/D — крен.
- Упал — респаун **на старте** (чекпоинты только по выбору в меню).
- Любое препятствие должно проходиться человеком; у скоростных (прыжок, петля) — зелёный пад, разгоняющий до нужной скорости.
- **Никаких замедлений**: красных падов-ограничителей нет, тормозит только сам игрок.

## Как устроены уровни

```
LevelLibrary.get(n) ──► LevelPlan (чистые данные) ──► new Course(world, mats, plan) ──► меши + физика
        ▲                         │
   generator.ts            segments: [{ type, params }, …]
   (сид = hash(n, попытка))       │
                           каталог: layout() — без построения; build(kit) — с построением
```

- **LevelPlan** (`src/levels/types.ts`) полностью определяет уровень: сид, сложность, название, высоту старта,
  список сегментов с параметрами и сигнатуру. План можно вывести (`npm run levels -- --plan N`), сохранить
  или написать руками (см. `classic.ts`).
- **Детерминизм**: уровень N одинаков на любой машине. Сид = `hashSeed('car-parkour', N, попытка)`, ГСЧ — mulberry32.
  Нельзя использовать `Math.random()` в `randomize`/`layout`/`build` — только переданный `rng` (или
  детерминированные функции от параметров).
- **Сложность** `difficultyFor(n) = 1 − e^(−(n−1)/14)`: 0 на уровне 1, ≈0.47 на 10-м, ≈0.74 на 20-м, → 1.
  От неё зависят число препятствий (4–10), доступные типы (`minDifficulty`) и параметры каждого типа.
- **Сборка плана** (`generate`): старт → N раз [связка (с вероятностью 0.7) → препятствие] → финиш.
  Препятствие выбирается взвешенно (`weight(d)`); повтор типа внутри уровня в 3 раза менее вероятен;
  максимум 2 одинаковых на уровень, никогда два подряд.
- **Проверки при сборке**:
  - *следы*: `layout().path` + `halfWidth` + `height` каждого нового сегмента не должны пересекать уже
    поставленные (кроме соседа) — трасса никогда не проходит сквозь себя;
  - *курс*: связки держат общий курс в пределах ±60° от +Z, трасса не разворачивается;
  - *высота*: связки подтягивают высоту; стартовая высота выбирается так, чтобы низшая точка была
    ≥ `MIN_TRACK_ALTITUDE` (выше крыш города);
  - *разнообразие*: минимум 4 разных типа препятствий на уровень.
  Если собрать не удалось, берётся следующая попытка (другой сид).
- **Неповторяемость**: `LevelLibrary` выдаёт уровни по порядку и отбрасывает план, если совпадает
  (а) его сигнатура — квантованные параметры всех сегментов (`signature()`), или
  (б) последовательность типов препятствий любого предыдущего уровня. Поэтому с ростом числа уровней
  они не повторяются ни «по числам», ни «по ощущениям». `npm run levels -- 300` это проверяет.

## Контракт сегмента (`SegmentDef`, `src/levels/types.ts`)

| Поле | Смысл |
|---|---|
| `type` | уникальный id (`'presses'`) — хранится в плане |
| `kind` | `'obstacle'` — выбирается генератором; `'connector'` — связка; `'fixed'` — старт/финиш |
| `title`, `summary` | баннер в игре и описание для меню/документации |
| `minDifficulty`, `weight(d)` | с какой сложности доступен и насколько часто выбирается |
| `randomize(rng, d, ctx)` | параметры из сида; `ctx` — курс, высота, предыдущий тип |
| `layout(start, p)` | **чистая** раскладка: `exit`, `path`, `halfWidth`, `height`. Без побочных эффектов |
| `build(kit, start, p)` | строит сегмент через `Kit`, возвращает выходной курсор — **тот же**, что `layout().exit` |
| `signature(p)` | короткая квантованная строка значимых параметров (для уникальности уровней) |

Инварианты:
1. `layout` и `build` используют одни и те же функции геометрии (`frames.ts`), поэтому планируемая и
   построенная трассы совпадают. Выход сегмента — на поверхности дороги, курс продолжается ровно.
2. Скорость на входе неизвестна (сегменты идут в любом порядке). Красных падов-ограничителей в игре нет:
   скоростью управляет игрок. Прыжки и петли начинаются с зелёного пада `kit.speedGate(start, v)`, который
   **только разгоняет** до `v`; более быструю машину он не трогает, поэтому посадочные горки рассчитаны
   с запасом (проверено ботом до 55 м/с на входе).
3. Препятствие регистрирует секцию `kit.section(title, sub, start, spawnAhead)` — баннер и чекпоинт.
   Точка респауна должна позволять пройти препятствие с места (например, разгон с зелёным падом).
4. `path` покрывает всю площадь сегмента, а `halfWidth`/`height` — габариты движущихся частей;
   иначе генератор может положить следующий сегмент поверх.
5. Препятствие должно быть проходимым: проверь ботом (см. ниже) на нескольких фазах `simTime`.

## Как добавить новое препятствие

1. Если нужен новый «строительный блок» (меш + коллайдеры + движение), добавь метод в `src/track/kit.ts`
   по образцу `press()` или `pendulum()`: декор через `b.addDecor`, статические коллайдеры через `b.collider`,
   движущиеся части через `b.addKinematic(object, (t, p, q) => {...}, [ColliderDesc…])`.
2. Создай `src/levels/catalog/<name>.ts`:

```ts
import type { SegmentDef } from '../types';
import { obstacleRoadLength, obstacleZ, straightLayout, TAU } from './common';

interface P extends Record<string, unknown> { spacing: number; units: { period: number; phase: number }[] }

export const hammers: SegmentDef<P> = {
  type: 'hammers',
  kind: 'obstacle',
  title: 'МОЛОТЫ',
  summary: '2–5 молотов бьют по дороге сверху',
  minDifficulty: 0.3,
  weight: () => 1,
  randomize(rng, d) {
    const n = Math.round(2 + 3 * d);
    return { spacing: rng.range(24, 30), units: Array.from({ length: n }, () => ({ period: rng.range(3, 5), phase: rng.range(0, TAU) })) };
  },
  layout: (s, p) => straightLayout(s, obstacleRoadLength(p.units.length, p.spacing), 12, 14),
  build(kit, s, p) {
    kit.section('МОЛОТЫ', 'Проскочи между ударами', s, 2);
    const out = kit.road(s, obstacleRoadLength(p.units.length, p.spacing), 22);
    kit.speedGate(s, 18, undefined, 22);
    p.units.forEach((u, i) => kit.hammer(s, obstacleZ(i, p.spacing), u.period, u.phase)); // новый блок в Kit
    return out;
  },
  signature: (p) => `K${p.units.length}`,
};
```

3. Добавь его в `CATALOG` в `src/levels/catalog/index.ts`.
4. `npm run typecheck` и `npm run levels -- 200`: новый тип должен появиться в статистике, ошибок быть не должно.
5. Проверь в браузере (`npm run dev`, консоль):
   ```js
   __dev.level(20)                 // уровень, где встречается препятствие (см. npm run levels)
   __dev.goto('МОЛОТЫ')            // старт секции
   __dev.bot(15, { speed: 18 })    // бот едет по осевой; lat: 5 — со смещением вбок
   ```
6. Допиши строку в таблицу ниже (или обнови её через `npm run levels -- --catalog`).

Важно: добавление нового типа меняет сгенерированные уровни (другие веса и выбор) — это нормально.
Если нужно сохранить конкретные уровни неизменными, запиши их планы явно, как `classic.ts`.

## Физика — на что обратить внимание

- Прыжки проектируются расчётом (`src/levels/jumpMath.ts`): по скорости с падов, углу трамплина и зазору
  подбирается наклон и длина посадочной горки, чтобы машина долетала при скорости от v−4 до v+8 м/с.
- Петля — каплевидная спираль: боковой сдвиг линеен по длине дуги, поэтому машина проходит её без руления.
  Скорость на входе — `loopSpeed()`; верхний радиус не меньше 9 м (иначе нос машины цепляет полотно).
- Давящие препятствия останавливаются над дорогой (пресс — на 1.2 м), чтобы машину сминало, а не
  проталкивало сквозь трассу.
- Пропеллеры не достают до краёв дороги на `PROP_LANE` (2.5 м при ширине машины 1.9 м): по краю можно
  проскочить без ожидания, но сместился к стойке на ~0.3 м — и законцовка лопасти сбивает машину.
  У законцовок свой коллайдер, видимая и физическая длина лопасти совпадают.
- Мельницы висят ниже длины лопасти: лопасти ныряют в прорезь дороги (`kit.slottedRoad` режет только меши,
  коллайдер сплошной — колёса не проваливаются) и метут всю ширину на высоте машины, без безопасной полосы.
  Такая лопасть, прижав машину к дороге, продавила бы её сквозь трассу (кинематическое тело не остановить),
  поэтому она помечена `addKinematic(…, { cutsThrough: true })`: `Vehicle.afterStep` делает её «призраком» —
  контакт остаётся (смятие, урон), но без импульсов (`Vehicle.hooks` → `filterContactPair`), а машину сносит
  по горизонтальной скорости лопасти. Хуки Rapier работают, только если в `world.step` передана `EventQueue`.
  Остальные препятствия не помечены, их контакты обычные.
- Аркадный дрифт (`Vehicle.step`, `DRIFT_*`): начинается **только ручником** на скорости > 9 м/с, дальше
  держится, пока машина под углом. Ассист держит угол заноса у цели, которую выбирает руль: в сторону
  заноса — ~37°, нейтраль — ~25°, контррулёж — ~13° (контррулёж держит занос, а не разворачивает машину);
  передние колёса в заносе почти не рулят — рысканием управляет ассист. Без газа или с тормозом цель 0 —
  машина выпрямляется, дрифт кончается. «Назад» включает задний ход только почти на месте (< 1.5 м/с),
  на ходу — это тормоз. Скольжение считается относительно поверхности (карусель, платформы).
- Детектор падения: машина ниже последней точки контакта на 9+ м и под ней нет трассы (луч вниз), либо
  упала на 45+ м.
